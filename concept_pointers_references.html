Concept: Pointers vs. References (Pointers සහ References)

Beginner Level: The Core Idea

Both pointers and references allow you to indirectly access another variable. They are tools to work with a variable's memory location rather than its value directly.

Analogy (උපමාව)

Pointer (`*`): A pointer is like a piece of paper where you've written down a friend's home address.

  • The paper itself has its own location (it's a variable).
  • The address written on it can be changed to a different friend's address.
  • The paper could be blank (a `nullptr`).
  • To visit the friend, you have to read the address and then go there (dereference with `*`).

Reference (`&`): A reference is like a nickname for your friend.

  • It's not a separate thing; it's just another name for the *exact same person*.
  • Once you give someone a nickname, you can't assign that nickname to someone else.
  • A nickname cannot refer to nobody (cannot be null).
  • When you use the nickname, you are directly talking to your friend (no special operator needed).

Sinhala (සිංහල):

  • Pointer (`*`): Pointer එකක් කියන්නේ ඔයා යාලුවෙක්ගේ ගෙදර address එක ලියපු කොල කෑල්ලක් වගේ. ඒ කොලේ තියෙන address එක මකලා වෙන යාලුවෙක්ගේ address එකක් ලියන්න පුලුවන්. කොලේ හිස්ව තියෙන්නත් පුලුවන් (`nullptr`).
  • Reference (`&`): Reference එකක් කියන්නේ ඔයාගේ යාලුවාට දාපු අන්වර්ථ නාමයක් (nickname) වගේ. ඒක වෙනම කෙනෙක් නෙවෙයි, ඒ යාලුවාමයි. ඒ නම වෙන කෙනෙක්ට දෙන්න බෑ, ඒ නමින් කතා කරද්දී කෙලින්ම යාලුවා එක්කමයි කතා කරන්නේ.

Intermediate Level: Syntax and Comparison

FeaturePointerReference
Declaration Syntaxint* ptr;int& ref = var;
InitializationCan be uninitialized (dangerous).Must be initialized when declared.
NullabilityCan be `nullptr`.Cannot be null. Must refer to a valid variable.
ReassignmentCan be changed to point to another variable.Cannot be changed to refer to another variable. It's bound for life.
Accessing ValueRequires dereferencing: `*ptr`Used directly like the original variable: `ref`
MemoryHas its own memory address.Shares the same memory address as the original variable.

Code Example: Demonstrating the Differences

C++
#include <iostream>
using namespace std;

void pointerExample() {
    cout << "--- POINTER EXAMPLE ---" << endl;
    int x = 10, y = 20;
    int* ptr = &x; // Points to x
    cout << "Pointer points to value: " << *ptr << endl;

    ptr = &y; // Can be reassigned to point to y
    cout << "Pointer now points to value: " << *ptr << endl;

    *ptr = 100; // Modifies the variable it points to (y)
    cout << "Value of y is now: " << y << endl;
}

void referenceExample() {
    cout << "\n--- REFERENCE EXAMPLE ---" << endl;
    int x = 10, y = 20;
    int& ref = x; // MUST be initialized. ref is now an alias for x.

    cout << "Reference refers to value: " << ref << endl;
    ref = y; // This assigns the VALUE of y to x. It does NOT rebind the reference.
    cout << "Value of x after 'ref = y': " << x << endl; // x is now 20
}

int main() {
    pointerExample();
    referenceExample();
    return 0;
}

Practical Application: Passing Arguments to Functions

One of the most important uses of pointers and references is to control how data is passed to functions. This allows us to avoid costly copies and to modify the original variables from within a function.

  1. Pass-by-Value: A copy of the variable is made. The function works on the copy. The original variable is unaffected. (Default behavior).
  2. Pass-by-Pointer: The memory address of the variable is passed. The function can use the address to access and modify the original variable.
  3. Pass-by-Reference: An alias (reference) to the original variable is created. The function works on the alias, which directly modifies the original variable. This is often safer and has cleaner syntax than pointers.

Code Example: Comparing All Three Methods

C++
#include <iostream>
using namespace std;

// 1. Pass-by-Value: 'num' is a copy. Original is not changed.
void modifyByValue(int num) {
    num = 100;
}

// 2. Pass-by-Pointer: 'numPtr' holds the address. We can change the original.
void modifyByPointer(int* numPtr) {
    if (numPtr != nullptr) { // Good practice to check for null
        *numPtr = 200;
    }
}

// 3. Pass-by-Reference: 'numRef' is an alias for the original variable.
void modifyByReference(int& numRef) {
    numRef = 300;
}

int main() {
    int myVar = 10;
    cout << "Initial value: " << myVar << endl;

    // --- Pass by Value ---
    modifyByValue(myVar);
    cout << "After modifyByValue: " << myVar << endl; // Unchanged

    // --- Pass by Pointer ---
    modifyByPointer(&myVar);
    cout << "After modifyByPointer: " << myVar << endl; // Changed

    // Reset value for next test
    myVar = 10;

    // --- Pass by Reference ---
    modifyByReference(myVar);
    cout << "After modifyByReference: " << myVar << endl; // Changed

    return 0;
}

Output and Analysis

Initial value: 10
After modifyByValue: 10
After modifyByPointer: 200
After modifyByReference: 300

As you can see, only pass-by-pointer and pass-by-reference were able to modify the original `myVar` in `main()`. Pass-by-value only modified its local copy.

Advanced Level: When to Use Which?

  • Use Pointers when:
    • You need "optional" access. A function parameter can be `nullptr` to signify "no value provided".
    • You need to change what you are pointing to during the variable's lifetime.
    • You are working with dynamic memory allocation (`new` and `delete`).
    • You need to perform pointer arithmetic (e.g., iterating through an array).
  • Use References when:
    • You need an alias that is guaranteed to refer to something valid. This makes code safer.
    • You want to pass a large object to a function efficiently (avoiding a copy) and with clean syntax. This is called "pass-by-reference".
    • Implementing operator overloading (e.g., `operator=`).
    • You want to ensure the alias cannot be rebound to another variable after initialization.

Rule of Thumb

Prefer references over pointers for function parameters when you need to modify the original argument or avoid a copy, and you are certain the argument will not be null. They are safer and have a cleaner syntax. Use pointers when you need the flexibility they offer (reassignment, nullability, dynamic memory).
