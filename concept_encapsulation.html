Concept: Encapsulation (ආවරණය)

Beginner Level: What is Encapsulation?

English: Encapsulation is like putting things in a capsule. It's the bundling of data (attributes) and the methods (functions) that work on that data into a single unit (a class). A key part of this is **data hiding**: protecting the data from outside interference.

Sinhala (සිංහල): Encapsulation කියන්නේ capsule එකක් ඇතුලට දේවල් දානවා වගේ දෙයක්. ඒ කියන්නේ, data (ගුණාංග) සහ ඒ data එක්ක වැඩ කරන methods (ක්‍රියා) එකට එකතු කරලා, එකම unit එකක් (class එකක්) ඇතුලට දාන එක. මෙහි වැදගත්ම කොටසක් තමයි **data hiding**: ඒ කියන්නේ data ටික පිටතින් එන අනවශ්‍ය බලපෑම් වලින් ආරක්ෂා කරන එක.

Real-World Scenario

English: Think of a television. You, the user, have a remote control (the public interface) with buttons like `powerOn()`, `changeChannel()`, and `increaseVolume()`. You don't have direct access to the internal electronic circuits, wires, and screen components (the private data). The plastic casing of the TV **encapsulates** all the complex parts and provides you with a simple, safe interface to interact with it.

Sinhala (සිංහල): Television (TV) එකක් ගැන හිතන්න. ඔයාට TV එක control කරන්න remote control එකක් (public interface) තියෙනවා. ඒකෙ `powerOn()`, `changeChannel()`, `increaseVolume()` වගේ buttons තියෙනවා. TV එක ඇතුලේ තියෙන electronic circuits, wires වගේ දේවල් (private data) වලට ඔයාට කෙලින්ම access කරන්න බෑ. TV එකේ plastic කවරය විසින් මේ සංකීර්ණ කොටස් ඔක්කොම **encapsulate** (ආවරණය) කරලා, ඔයාට පාවිච්චි කරන්න සරල, ආරක්ෂිත interface එකක් දීලා තියෙනවා.

Intermediate Level: Implementation with Access Specifiers

Encapsulation is implemented in C++ using **access specifiers**: `public`, `private`, and `protected`.

  • `public` members: Accessible from anywhere outside the class. This forms the object's interface.
  • `private` members: Accessible only by member functions inside the class itself. This is used for data hiding.
  • `protected` members: Similar to private, but also accessible by derived (child) classes.

The standard practice is to make all data members `private` and provide `public` methods (called getters and setters) to access or modify them in a controlled way.

Sample Code 1: A `Student` Class with Validation

In this example, the `studentGrade` is `private`. You cannot set it to an invalid value like 'Z' directly. You must use the `setGrade` method, which contains validation logic to ensure the grade is valid. This protects the object's integrity.

C++
#include <iostream>
#include <string>
using namespace std;
class Student {
private:
    string studentName;
    char studentGrade;
public:
    Student(const string& name) : studentName(name), studentGrade('F') {}
    void setGrade(char newGrade) {
        if (newGrade >= 'A' && newGrade <= 'F' && newGrade != 'E') {
            studentGrade = newGrade;
        } else {
            cout << "Error: Invalid grade." << endl;
        }
    }
    char getGrade() { return studentGrade; }
    string getName() { return studentName; }
};
int main() {
    Student alice("Alice");
    // alice.studentGrade = 'Z'; // COMPILE ERROR! Cannot access private member.
    alice.setGrade('X'); // Fails safely
    alice.setGrade('A'); // Succeeds
    cout << alice.getName() << 's grade: ' << alice.getGrade() << endl;
    return 0;
}

Sample Code 2: A `Stopwatch` Class Managing State

This example shows how encapsulation is crucial for managing an object's internal state. The `Stopwatch` has private members `isRunning` and `startTime`. The user cannot directly change these. They can only interact with the `start()` and `stop()` methods. This prevents logical errors, like stopping a watch that isn't running or getting a time from a stopped watch.

C++
#include <iostream>
#include <chrono> // For time functions

class Stopwatch {
private:
    // Internal state is completely hidden
    bool isRunning;
    std::chrono::time_point<std::chrono::high_resolution_clock> startTime;

public:
    Stopwatch() : isRunning(false) {}

    void start() {
        if (!isRunning) {
            isRunning = true;
            startTime = std::chrono::high_resolution_clock::now();
            std::cout << "Stopwatch started." << std::endl;
        } else {
            std::cout << "Stopwatch is already running." << std::endl;
        }
    }

    void stop() {
        if (isRunning) {
            isRunning = false;
            std::cout << "Stopwatch stopped." << std::endl;
        }
    }

    double getElapsedTime() {
        if (isRunning) {
            auto endTime = std::chrono::high_resolution_clock::now();
            std::chrono::duration<double> elapsed = endTime - startTime;
            return elapsed.count();
        }
        std::cout << "Stopwatch is not running. Returning 0." << std::endl;
        return 0.0;
    }
};

int main() {
    Stopwatch timer;

    // User interacts through the clean, public interface
    timer.start();

    // Pretend to do some work
    for(long i = 0; i < 200000000; ++i);

    std::cout << "Elapsed time: " << timer.getElapsedTime() << " seconds" << std::endl;

    timer.stop();

    return 0;
}

Advanced Level: Benefits of Encapsulation

  • Data Integrity and Security: By hiding data and providing controlled access through methods, we can enforce validation rules and prevent the object from entering an invalid or inconsistent state.
  • Flexibility and Maintainability: The internal implementation of a class can be changed without breaking the code that uses it. For example, we could change how `studentGrade` is stored internally (e.g., as an integer 1-5), but as long as the public `getGrade()` and `setGrade()` methods still work with characters, the external code will not be affected.
  • Reduced Complexity: It simplifies the use of a class for other developers. They only need to know the public interface, not the complex details happening inside. This is the link between Encapsulation and Abstraction.
  • Better Debugging: If there's a bug related to an object's state, you only need to debug the public methods that modify that state, rather than searching through the entire codebase for places where the data might have been changed directly.

Encapsulation vs. Abstraction

These two concepts are related but distinct. Encapsulation is the *mechanism* of bundling data and hiding it. Abstraction is the *design principle* of hiding complexity. Encapsulation is one of the primary ways we achieve abstraction.

Sinhala (සිංහල): Encapsulation සහ Abstraction සම්බන්ධයි, ඒත් වෙනස්. Encapsulation කියන්නේ data හංගන *යාන්ත්‍රණය*. Abstraction කියන්නේ සංකීර්ණ බව හංගන *design මූලධර්මය*. Abstraction එක ලබාගන්න අපි පාවිච්චි කරන ප්‍රධාන ක්‍රමයක් තමයි Encapsulation.
