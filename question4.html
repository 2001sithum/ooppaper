Question 4: Advanced Class Features & Relationships

4 (a) - Overloading vs. Overriding

Describe the differences between overloading and overriding functions in C++.

Function overloading and function overriding are two key polymorphism concepts in C++, but they operate in fundamentally different ways. Overloading is resolved at compile-time, while overriding is resolved at run-time.

Comparison Table

Feature Function Overloading (Compile-Time) Function Overriding (Run-Time)
Scope Occurs within the same class. Occurs between a base class and a derived class.
Function Signature Functions must have the same name but different parameters. Functions must have the exact same name and parameters.
Purpose To provide multiple ways to perform a similar operation with different inputs. To allow a derived class to provide a specialized implementation of a base class function.
Keywords No special keywords required. The base class function must be marked `virtual`. Best practice to use `override` in the derived class.

Code Example: Demonstrating Both

C++
#include <iostream>
using namespace std;

// --- Overriding Example ---
class Animal {
public:
    virtual void makeSound() { cout << "Generic Animal Sound" << endl; }
};
class Dog : public Animal {
public:
    void makeSound() override { cout << "Woof!" << endl; }
};

// --- Overloading Example ---
class Printer {
public:
    void print(int i) { cout << "Printing an integer: " << i << endl; }
    void print(double d) { cout << "Printing a double: " << d << endl; }
};

int main() {
    cout << "--- Overriding Demo ---" << endl;
    Animal* pAnimal = new Dog();
    pAnimal->makeSound(); // At runtime, this calls Dog::makeSound()
    delete pAnimal;

    cout << "\n--- Overloading Demo ---" << endl;
    Printer myPrinter;
    myPrinter.print(100);      // Compiler chooses the int version
    myPrinter.print(3.14);    // Compiler chooses the double version

    return 0;
}

4 (b) - Protected Inheritance

Describe what happens to base class members when protected inheritance is used.

Key Concepts

  • Access Specifiers: `public`, `protected`, and `private` keywords that control the visibility of class members.
  • Inheritance Modes: When deriving a class, you can specify `public`, `protected`, or `private` inheritance, which changes the access level of inherited members in the derived class.

How `protected` Inheritance Works

When you use `protected` inheritance (e.g., `class Derived : protected Base;`), the access specifiers of the members inherited from the base class are modified as follows within the context of the derived class:

  • Base class `public` members become `protected` in the derived class.
  • Base class `protected` members remain `protected` in the derived class.
  • Base class `private` members are inaccessible.

The key takeaway is that `protected` inheritance makes all inherited members accessible only to the derived class and any further derived classes, but not to the outside world.

4 (c) - Class Implementation & Object Copying

Considering the `Temp` class, rewrite it using suitable access specifiers. Create the `main` function to create `temp1`, initialize it to 35, create a copy `temp2`, set `temp2` to 40, and write down the expected outputs.

Key Concepts

  • Encapsulation: The practice of making data members `private` and providing `public` methods (getters/setters) to interact with them.
  • Copy Initialization: Creating an object as a copy of another (`Temp temp2 = temp1;`). This invokes the copy constructor.
  • Value Semantics: By default, C++ objects have value semantics. When you copy an object, you get a new, independent object. Changes to the copy do not affect the original.

Rewritten Class and `main()` function

C++
#include <iostream>
using namespace std;
class Temp {
private: // Encapsulate the data member
    double celc;
public:  // Provide a public interface
    Temp(double temp) : celc(temp) {}
    void setTemp(double temp) { celc = temp; }
    double getTemp() { return celc; }
};

int main() {
    Temp temp1(35.0);
    Temp temp2 = temp1; // Creates an independent copy
    temp2.setTemp(40.0); // Modifies only temp2, not temp1

    cout << "Value of temp1: " << temp1.getTemp() << endl;
    cout << "Value of temp2: " << temp2.getTemp() << endl;
    return 0;
}

Expected Output

Value of temp1: 35
Value of temp2: 40

4 (d) - Friend Functions

Write a friend function `getCat()` for the following program.

Key Concepts

  • `friend` Keyword: A mechanism to grant a non-member function or another class access to the `private` and `protected` members of the class where the friend declaration is made.
  • Breaking Encapsulation: `friend` functions intentionally break encapsulation. They should be used sparingly, only when an external function truly needs intimate access to a class's internal state.
  • Factory Function: The `getCat` function acts as a simple factory function—its job is to create and return an instance of a class.

Complete Program with `friend` Function

C++
#include <iostream>
#include <string>
using namespace std;
class Cat {
private:
    string name;
    int age;
public:
    Cat(string name_val, int age_val) : name(name_val), age(age_val) {}
    void sayCat() { cout << "Name is " << name << " and age is " << age << "." << endl; }
    // The friend declaration gives getCat() access to private members.
    // (Though in this specific case, it doesn't need it as it just uses the public constructor)
    friend Cat getCat(string name, int age);
};

// Friend function definition. Note: no 'Cat::' prefix.
Cat getCat(string name, int age) {
    Cat newCat(name, age);
    return newCat;
}

int main() {
    Cat cat = getCat("Tom", 10);
    cat.sayCat();
    return 0;
}

Key Concepts

  • Operator Overloading: A form of compile-time polymorphism that allows you to provide a custom implementation for C++ operators for your own classes.
  • Syntax: Declared as a member function `ReturnType operatorOp(Parameters)` or as a non-member function.
  • Comparison Operators: When overloading comparison operators like `<`, `>`, `==`, etc., they should typically return a `bool` and be declared as `const` member functions because they should not modify the object.
