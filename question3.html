Question 3: Core Object-Oriented Concepts

3 (a) - Ambiguity in Multiple Inheritance

Describe how C++ handles ambiguity in multiple inheritance using code segments as examples.

Key Concepts

  • Multiple Inheritance: A feature where a class can inherit from more than one base class, combining their features.
  • Ambiguity: A compilation error that occurs when the compiler cannot determine which member function or variable to use because it exists in multiple base classes with the same name.
  • Scope Resolution Operator (::): An operator used to specify which namespace or class a member belongs to, thereby resolving ambiguity.

Explanation of the Problem

When a derived class inherits from two or more base classes that happen to have a member (function or variable) with the exact same name and signature, an ambiguity arises. If you try to call that member through an object of the derived class, the compiler is confused. It doesn't know which base class's version of the member you intend to use.

The Solution: Scope Resolution Operator

C++ handles this ambiguity by requiring the programmer to explicitly state which base class's member they want to access. This is done using the Scope Resolution Operator (::).

The syntax is: objectName.ClassName::memberName.

Diagram: The Ambiguity Scenario

Inheritance Structure

Code Example

C++
#include <iostream>
using namespace std;
class BaseA {
public:
    void display() { cout << "Function from BaseA called." << endl; }
};
class BaseB {
public:
    void display() { cout << "Function from BaseB called." << endl; }
};
class Derived : public BaseA, public BaseB {};

int main() {
    Derived d_obj;
    // d_obj.display(); // Error: request for member 'display' is ambiguous
    cout << "Resolving ambiguity:" << endl;
    d_obj.BaseA::display();
    d_obj.BaseB::display();
    return 0;
}

3 (b) - Function Overloading

Write a C++ program that defines a class `Calculator` with overloaded `add()` functions for two integers, three integers, two floats, and two strings.

Key Concepts

  • Function Overloading: A form of compile-time polymorphism where multiple functions can have the same name but different parameters (in number, type, or order).
  • Function Signature: The combination of a function's name and its parameter list. The return type is NOT part of the signature for overloading purposes.
  • Name Mangling: The process used by the C++ compiler to give each function a unique internal name based on its signature, which enables overloading.

Complete Program: `Calculator` Class

C++
#include <iostream>
#include <string>
using namespace std;
class Calculator {
public:
    int add(int a, int b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
    double add(double a, double b) { return a + b; }
    string add(const string& a, const string& b) { return a + b; }
};
int main() {
    Calculator myCalc;
    cout << "Sum (10, 20): " << myCalc.add(10, 20) << endl;
    cout << "Sum (10, 20, 30): " << myCalc.add(10, 20, 30) << endl;
    cout << "Sum (5.5, 4.2): " << myCalc.add(5.5, 4.2) << endl;
    cout << "Concat ('OOP ', 'Fun'): " << myCalc.add("OOP ", "Fun") << endl;
    return 0;
}

3 (c) - Copy Constructor

Describe what a copy constructor is with an example.

Key Concepts

  • Copy Constructor: A special constructor that creates a new object as a copy of an existing object. Signature: `ClassName(const ClassName& other)`.
  • Shallow Copy: Default behavior. Copies member values. If a member is a pointer, only the address is copied, leading to two pointers pointing to the same memory.
  • Deep Copy: Required for classes with dynamic memory. Allocates new memory for pointers and copies the data, ensuring the new object is fully independent.

Deep Dive: Shallow Copy vs. Deep Copy

A shallow copy is dangerous for classes managing resources like memory or files. When a shallow-copied object is destroyed, it frees the memory. When the other object is destroyed, it tries to free the *same* memory again, leading to a crash (double free error). A deep copy prevents this by giving each object its own resource to manage.

Code Example: Implementing a Deep Copy

C++
#include <iostream>
#include <cstring>
using namespace std;

class StringWrapper {
private:
    char* data;
public:
    StringWrapper(const char* str = "") {
        data = new char[strlen(str) + 1];
        strcpy(data, str);
    }
    // Deep Copy Constructor
    StringWrapper(const StringWrapper& other) {
        cout << "** Deep Copy Constructor Called **" << endl;
        data = new char[strlen(other.data) + 1]; // 1. Allocate new memory
        strcpy(data, other.data); // 2. Copy the data
    }
    ~StringWrapper() { delete[] data; }
    void print() { cout << data << endl; }
};

int main() {
    StringWrapper original("Hello");
    StringWrapper copy = original; // Invokes copy constructor
    original.print();
    copy.print();
    return 0; // No crash, as each object manages its own memory.
}

3 (d) - Destructor

Describe what a destructor in C++ is using examples.

Key Concepts

  • Destructor: A special member function (`~ClassName()`) that is automatically called when an object's lifetime ends (e.g., it goes out of scope or is deleted).
  • Purpose: Its primary purpose is to release resources acquired by the object during its lifetime, such as dynamic memory, file handles, or network connections. This prevents resource leaks.
  • Virtual Destructor: A base class should always have a `virtual` destructor if it's meant to be used polymorphically (i.e., deleting a derived object through a base class pointer). This ensures the correct chain of destructors is called.

Code Example: Resource Management

C++
#include <iostream>
using namespace std;

class ResourceManager {
private:
    int* data;
public:
    ResourceManager() {
        data = new int[100]; // Acquire resource (memory) in constructor
        cout << "Resource acquired." << endl;
    }
    ~ResourceManager() {
        delete[] data; // Release resource in destructor
        cout << "Resource released. Memory leak prevented." << endl;
    }
};

void testFunction() {
    cout << "Entering testFunction..." << endl;
    ResourceManager res; // Object is created here
    cout << "Exiting testFunction..." << endl;
} // 'res' goes out of scope, destructor is automatically called here

int main() {
    testFunction();
    return 0;
}

3 (e) - Out-of-Class Member Function Definition

Define the `getDist()` function for the following program... The function needs to be written outside the class.

Key Concepts

  • Separation of Interface and Implementation: It's good practice to separate the declaration of a class (its interface, in a header file `.h`) from the definition of its member functions (its implementation, in a source file `.cpp`).
  • Scope Resolution Operator (`::`): When defining a member function outside its class, you must use the scope resolution operator to tell the compiler which class the function belongs to. Syntax: `ReturnType ClassName::functionName(params) { ... }`.

Complete Program with Out-of-Class Definition

C++
#include <iostream>
using namespace std;
class Distance {
private:
    int feet;
    int inches;
public:
    Distance(int ft, int in) : feet(ft), inches(in) {}
    // Function is only DECLARED here
    int getDist();
};

// Function is DEFINED here, outside the class, using scope resolution
int Distance::getDist() {
    return (feet * 12) + inches;
}

int main() {
    Distance dist(10, 5);
    cout << "Total distance in inches: " << dist.getDist() << endl; // Output will be 125
    return 0;
}

3 (f) - Abstraction

Explain why abstraction is essential for developing real-world applications.

Abstraction is the principle of hiding complex implementation details and showing only the essential, relevant information to the user. It is the foundation of good software design.

Why Abstraction is Essential:

  1. Manages Complexity: Real-world systems are incredibly complex. Abstraction allows us to model these systems by breaking them into smaller, understandable components. A developer using a `DatabaseConnection` object only needs to know about `connect()` and `query()` methods, not the underlying network protocols or SQL driver implementation.
  2. Improves Maintainability: It decouples the interface from the implementation. The internal workings of a class can be completely rewritten for better performance or to fix bugs. As long as the public interface (the abstraction) remains unchanged, none of the code that uses the class needs to be modified.
  3. Enhances Team Collaboration: Different teams can work on different parts of a system concurrently. One team can develop a component while another team develops code that uses it, relying only on the agreed-upon public interface.
  4. Increases Security and Safety: By exposing only a limited set of public methods, abstraction prevents users from manipulating an object's internal state in unintended or harmful ways, thus ensuring data integrity.
