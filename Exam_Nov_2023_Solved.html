1 (c) - Explain a pointer in C++

Explain what a pointer in C++ is.

A pointer in C++ is a special type of variable that does not store data directly but instead stores a **memory address**. Its purpose is to "point to" the location of another variable in memory.

  • Declaration: It's declared using an asterisk (`*`), like `int* ptr;`. This means `ptr` is a variable that can hold the address of an integer.
  • Address-of Operator (`&`): To get the memory address of a variable, you use the `&` operator (e.g., `ptr = &myVariable;`).
  • Dereference Operator (`*`): To access the *value* at the address a pointer holds, you use the `*` operator again (e.g., `cout << *ptr;`).

1 (d) - Explain array out-of-bounds access

Explain what happens when the following program is executed. You are not required to write down the output.

Key Concepts

  • Array Bounds: An array declared as `int array[2];` has valid indices `0` and `1`. The size is 2, but the maximum index is `size - 1`.
  • Undefined Behavior: Accessing an array outside of its valid bounds is a serious error in C++. The C++ standard does not define what should happen. This is called "Undefined Behavior" (UB).

Explanation

The program declares an integer array named `array` with a size of 2. This means it has two valid memory locations: `array[0]` and `array[1]`.

The code then attempts to access `array[3]` and `array[4]`. Both of these indices are **out of bounds** for the declared array.

When this happens, the program exhibits **Undefined Behavior**. This means there is no guaranteed outcome. Possible consequences include:

  1. The program might crash immediately with a segmentation fault.
  2. It might print "garbage" values—random data from whatever happens to be in those adjacent memory locations.
  3. It might seem to work correctly but silently corrupt other variables in the program, leading to strange bugs later on.
  4. The output can be different every time the program is run or on different computers/compilers.

In summary, the program attempts to read from memory locations it does not own, leading to unpredictable and dangerous behavior.

3 (c, d, e) - Concepts of `friend` and `operator overloading`

(c) Describe operator overloading.
(d) Describe the concept of `friend`.
(e) Describe the impact of `friend` towards encapsulation.

(c) Operator Overloading

Operator overloading is a feature in C++ that allows programmers to provide a custom meaning for an operator (like `+`, `-`, `<<`, `==`) for a user-defined type (a class or struct). It allows objects of a class to be used with operators in an intuitive way, similar to built-in types. For example, you can overload the `+` operator for a `ComplexNumber` class to perform complex number addition.

(d) The `friend` Concept

The `friend` keyword in C++ is a mechanism to grant special access rights. A non-member function or another class can be declared as a `friend` of a class. This declaration gives the friend function or friend class access to the `private` and `protected` members of the class that granted the friendship.

(e) Impact of `friend` on Encapsulation

The `friend` keyword intentionally **breaks encapsulation**. Encapsulation is the principle of hiding data and exposing only public methods to interact with it. By declaring a friend, a class creates a "back door" that allows an external entity to bypass this protection and directly access its internal state. While this is sometimes necessary for efficiency or for closely related classes (like iterators), it weakens the data hiding principle and should be used with caution.

4 (a) - "extend" relationship in UML use case diagrams

Explain the situations where you can use the "extend" relationship in UML use case diagrams.

In a UML use case diagram, the **"extend"** relationship is used to model **optional** or exceptional functionality. It specifies that one use case (the extending use case) may, under certain conditions, add behavior to another use case (the extended use case).

You use "extend" in these situations:

  1. Optional Functionality: When a piece of functionality is not always executed as part of the base use case. For example, a "Place Order" use case could be extended by a "Apply Discount Code" use case. Applying a discount is optional.
  2. Exceptional or Alternative Flows: When a specific condition triggers an alternative path. For example, a "Login" use case could be extended by a "Forgot Password" use case, which only runs if the user fails to log in and clicks the corresponding link.

The key idea is that the base use case is complete and can stand on its own without the extending use case.

5 (a) - Describe Polymorphism

Describe the concept of polymorphism with examples.

Polymorphism means "many forms". It's a core OOP principle that allows objects of different classes to be treated as objects of a common base class. The most powerful form is **run-time polymorphism**, achieved through `virtual` functions and inheritance.

It allows a single interface (a base class pointer) to represent different underlying forms (derived class objects). The same function call (`ptr->doAction()`) can execute different code depending on the actual type of the object `ptr` is pointing to at that moment.

Example

class Shape { public: virtual void draw() = 0; };
class Circle : public Shape { public: void draw() override { cout << "Draw Circle"; } };
class Square : public Shape { public: void draw() override { cout << "Draw Square"; } };

void drawAnyShape(Shape* s) {
    s->draw(); // This one line can draw a Circle or a Square
}

5 (d) - Describe the three types of inheritance

Describe the three (03) types of inheritance.
  1. Single Inheritance: This is the simplest form, where a derived class inherits from only **one** base class. It represents a straightforward "is-a" relationship (e.g., a `Car` is a `Vehicle`).
  2. Multiple Inheritance: A derived class inherits from **two or more** base classes simultaneously. This allows the derived class to combine the features of all its parents (e.g., a `FlyingCar` could inherit from both `Car` and `Airplane`).
  3. Multilevel Inheritance: A derived class is created from another derived class, forming a chain of inheritance (e.g., `Animal` -> `Mammal` -> `Dog`). The final class in the chain inherits properties from all its ancestors.
