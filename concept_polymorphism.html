Concept: Polymorphism (බහුරූපතාව)

Beginner Level: What is Polymorphism?

English: Polymorphism comes from Greek words "poly" (meaning many) and "morph" (meaning forms). In OOP, it's the ability of an object or function to take on many forms. The most common use is when a parent class reference is used to refer to a child class object, allowing the same code to work with different object types.

Sinhala (සිංහල): Polymorphism කියන වචනය එන්නේ "poly" (බොහෝ) සහ "morph" (ආකාර) කියන Greek වචන වලින්. OOP වලදී, මේකෙන් කියවෙන්නේ එකම object එකකට හෝ function එකකට විවිධ ආකාර (forms) ගන්න තියෙන හැකියාව. බහුලවම පාවිච්චි වෙන්නේ, parent class pointer එකක් child class object එකකට යොමු කරලා, එකම code එකෙන් විවිධ වර්ගයේ object එක්ක වැඩ කරන්න ඉඩ දීමයි.

Real-World Scenario

English: Think of a USB port. You can plug in a mouse, a keyboard, a flash drive, or a smartphone. The USB port (the interface) is the same, but the action performed depends on the device (the object) you connect. The USB port exhibits polymorphic behavior.

Sinhala (සිංහල): USB port එකක් ගැන හිතන්න. ඔයාට ඒකට mouse එකක්, keyboard එකක්, pen drive එකක්, smartphone එකක් වගේ ඕන දෙයක් plug කරන්න පුලුවන්. USB port එක (interface එක) එකමයි, ඒත් ඒකෙන් වෙන ක්‍රියාව රඳා පවතින්නේ ඔයා plug කරන device (object) එක මත. USB port එක polymorphic හැසිරීමක් පෙන්නනවා.

Intermediate Level: Types of Polymorphism in C++

C++ supports two main types of polymorphism:

1. Compile-Time (Static) Polymorphism

The decision of which function to call is made by the compiler at **compile time**. This is achieved through:

  • Function Overloading: Creating multiple functions with the same name but different parameters within the same scope. The compiler chooses the correct one based on the arguments you pass.
  • Operator Overloading: Assigning a new meaning to an existing operator (like `+`, `-`, `<<`) for a user-defined class.
C++ (Function Overloading)
void print(int i) { cout << "Integer: " << i; }
void print(string s) { cout << "String: " << s; }
print(10); // Compiler picks the first version
print("hello"); // Compiler picks the second version

2. Run-Time (Dynamic) Polymorphism

The decision of which function to call is delayed until **run time**. This is achieved through:

  • Function Overriding: A derived class provides its own specific implementation of a function that is already defined in its base class.
  • Virtual Functions: The `virtual` keyword is essential for this. It tells the compiler not to bind the function call at compile time, but to look it up at run time based on the object's actual type.
C++ (Function Overriding)
class Animal { public: virtual void makeSound() { cout << "..."; } };
class Dog : public Animal { public: void makeSound() override { cout << "Woof!"; } };

Animal* ptr = new Dog();
ptr->makeSound(); // At RUN-TIME, this calls the Dog's version.

Practical Application: Polymorphism with Collections

One of the most powerful uses of run-time polymorphism is to manage a collection of different objects that share a common base class. You can create an array or vector of base class pointers and store the addresses of various derived class objects in it. Then, you can loop through the collection and call the same virtual function on each element, and the correct version of the function will be executed for each object.

Code Example: A Zoo of Animals

C++
#include <iostream>
#include <vector>
#include <memory> // For std::unique_ptr
using namespace std;

class Animal {
public:
    virtual void makeSound() { cout << "Generic animal sound" << endl; }
    virtual ~Animal() {} // Virtual destructor is crucial!
};

class Dog : public Animal {
public:
    void makeSound() override { cout << "Woof! Woof!" << endl; }
};

class Cat : public Animal {
public:
    void makeSound() override { cout << "Meow!" << endl; }
};

class Duck : public Animal {
public:
    void makeSound() override { cout << "Quack!" << endl; }
};

int main() {
    // A collection of base class pointers (using modern smart pointers)
    vector<unique_ptr<Animal>> zoo;

    // Add different types of objects to the same collection
    zoo.push_back(make_unique<Dog>());
    zoo.push_back(make_unique<Cat>());
    zoo.push_back(make_unique<Duck>());
    zoo.push_back(make_unique<Dog>());

    cout << "--- Let's hear the sounds of the zoo ---" << endl;

    // Loop through the collection and call the same function on each object
    for (const auto& animal : zoo) {
        animal->makeSound(); // The correct function is called for each object
    }

    return 0;
}

Output of the Code

--- Let's hear the sounds of the zoo ---
Woof! Woof!
Meow!
Quack!
Woof! Woof!

Advanced Level: How Run-Time Polymorphism Works (Virtual Tables)

When a class has at least one `virtual` function, the compiler adds a hidden pointer to each object of that class, called the **virtual pointer** (or **vptr**). This `vptr` points to a static array of function pointers called the **virtual table** (or **vtable**).

The vtable contains the addresses of the virtual functions for that specific class. When you make a call like `basePtr->makeSound()`, the program follows these steps at run time:

  1. Access the object's `vptr`.
  2. Use the `vptr` to find the class's `vtable`.
  3. Look up the address of `makeSound()` in the `vtable`.
  4. Call the function at that address.

This mechanism, known as **dynamic dispatch**, allows the correct derived class function to be called even when using a base class pointer.

Virtual Destructors

If you plan to `delete` a derived class object through a base class pointer, the base class destructor **must** be declared `virtual`. If it is not, only the base class destructor will be called, leading to resource leaks from the derived class part of the object. This is a very common and serious bug.
